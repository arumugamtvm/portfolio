## 📋 Core Resume Framework

<table>
<tr><th>Section</th><th>What to Include</th><th>ATS Tip</th></tr>
<tr><td>Header</td><td>Name, email, phone, LinkedIn, GitHub, location (city only)</td><td>No tables/columns — plain text</td></tr>
<tr><td>Summary</td><td>2–3 lines: role title + top skills + one career achievement</td><td>Include job title keyword exactly</td></tr>
<tr><td>Skills</td><td>Categorized by type (see template below)</td><td>Match exact terms from job descriptions</td></tr>
<tr><td>Projects</td><td>2–4 AI projects with tech stack + metrics</td><td>Use numbers: "reduced latency by 40%"</td></tr>
<tr><td>Experience</td><td>Reverse chronological, STAR-formatted bullets</td><td>Action verb + tool + quantified result</td></tr>
<tr><td>Education</td><td>Degree, institution, year — certifications below</td><td>List relevant courses if recent grad</td></tr>
</table>

**1-page rule**: For under 3 years experience, keep it to 1 page. Every bullet must earn its spot.

## 🔢 Step-by-Step: Building Your AI Resume

1. **Start with the job description** — copy/paste it into a doc, highlight every technical skill mentioned. These become your keywords.
2. **Write your skills section first** — map your actual skills to the JD keywords. Don't lie; do use exact terminology.
3. **Write project bullets** — use format: "Built [what] using [tech], achieving [metric]." Add GitHub link.
4. **Write experience bullets** — same format. Start with action verb. Quantify every bullet.
5. **Write summary last** — 2–3 lines that echo the job title and top 3 skills from the JD.
6. **ATS check** — paste your resume into a plain .txt file. If it looks garbled, fix formatting.
7. **Human check** — show to a senior engineer. Ask: "Does this pass the 6-second scan?"

## 🎤 Practice Q&A

**Q: Why do you want to work in AI engineering?**

> A: "I've been drawn to the intersection of software and intelligence — specifically the moment when a model you built does something genuinely useful in the real world. My turning point was building a RAG system for [topic] — it could answer questions better than a keyword search I'd spent weeks on. That experience convinced me this is where I want to spend the next decade."

**Q: Walk me through your most impressive AI project.**

> A: "My most technically challenging project was [name]. The problem: [1 sentence]. I built a pipeline using [tech stack]. The hardest part was [specific challenge] — I solved it by [approach]. The result: [metric]. I can share the GitHub — it has a full README and demo."

**Q: How do you stay current with AI advancements?**

> A: "I follow [Andrej Karpathy, Simon Willison, Hugging Face blog]. I read 1–2 papers per week from Arxiv (I use the abstract + intro + results section method — rarely need the full paper). I also build small experiments with new tools — my GitHub has several weekend projects where I tested new models or frameworks."

## ⚠️ Common Mistakes to Avoid

- **Generic summaries** like "passionate data scientist seeking opportunity" — be specific
- **No GitHub links** — every project bullet needs a link; a resume without GitHub is invisible
- **"Worked on" or "helped with"** — use strong verbs: built, deployed, optimized, reduced, improved
- **Lying about skills** — if you list PyTorch, they WILL ask you to implement backprop
- **Same resume for every job** — swap the summary + reorder skills to match each JD
- **Applying without a referral when one is possible** — referrals 4x your callback rate
- **Following up more than once** — one polite follow-up after 7 days is professional; more is not
